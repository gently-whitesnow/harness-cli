# Repository Quality Harness

Standalone CLI для единообразной проверки качества репозиториев человеком, AI-агентом и — в будущем — CI.

Идея инструмента проста: переиспользуемые инженерные правила должны жить в исполняемых гейтах, а не в инструкциях агенту. Сейчас такие проверки часто реализуются громоздкими скриптами, копируются между репозиториями и постепенно расходятся. Harness собирает их в одном версионируемом инструменте.

## Граница ответственности

Репозиторий хранит знания, специфичные для продукта:

- код и бизнес-тесты;
- исполняемые контракты;
- архитектурные тесты конкретной системы;
- ADR с причинами долгосрочных решений.

Harness хранит переиспользуемые проверки поддержки и качества репозитория. Он запускает стандартный toolchain, считает общие метрики и показывает, каких доказательств качества не удалось обнаружить. Инструмент не пытается угадать правильную архитектуру проекта.

## План v0

Основной интерфейс:

```text
harness check [path]
```

Первая версия будет:

- обнаруживать .NET и TypeScript/Vite/React surfaces;
- запускать format, build, test, lint и typecheck;
- показывать maintainability hotspots и нормализованные дубликаты;
- обнаруживать известные test, integration и architecture capabilities;
- проверять компактность и расположение Markdown-документов;
- измерять длительность каждого гейта;
- поддерживать независимые `--only`, `--skip` и `explain`.

Каждая blocking-проверка должна быть детерминированной, объяснимой, достаточно быстрой, иметь низкий риск false positive и подтверждаться негативным тестом. Эвристические находки остаются advisory.

## Документационная политика

- `ROOT.md` — единый источник агентской навигации, не более 150 строк;
- `AGENTS.md` и `CLAUDE.md` — прямые относительные symlink на `ROOT.md`;
- `README.md` — краткий обзор, не более 150 строк;
- `adrs/**/*.md` — долговременные архитектурные решения;
- остальные tracked Markdown-файлы — повод для advisory finding.

## Не входит в v0

Автоматическое исправление кода, генерация архитектуры, repository manifest, CI enforcement, affected-test selection, cache и единый AI-readiness score.
