# Repository Quality Harness

CLI с единой рамкой качества для разных репозиториев. Он читает self-reported ответы из
tracked `.harness.json` и измеряет то, что можно одинаково проверить в любом репозитории.
Тесты, сборку и линтеры проекта харнес не запускает — за них отвечает CI самого проекта.

## Запуск

Из корня этого репозитория (нужен .NET 10 SDK):

```sh
dotnet run --project src/Harness -- init /path/to/repository
dotnet run --project src/Harness -- check /path/to/repository
```

`init` создаёт намеренно незавершённый `.harness.json`: каждый вопрос нужно разрешить после
исследования репозитория, а не заполнить догадкой или массовым suppress. По умолчанию
фиксируется текущая числовая версия; `--latest` включает новые вопросы текущего бинарника.
Существующий файл команда не перезаписывает и в Git не добавляет.

Путь можно не указывать для текущего репозитория. `harness help` показывает команды и
проверки. Обычный `check` печатает компактную строку со статусом для каждой проверки,
а причины и конкретные замечания раскрывает `--verbose`. Одну проверку можно запустить
отдельно: `harness check --only <check-id> [--verbose]`. Команда
`harness explain <check-id>` описывает смысл и исправление проверки.

## Как это работает

Эталон — рабочий [`.harness.json`](.harness.json) этого репозитория: в нём представлены все
формы ответа и секции конфигурации. `paths` служит навигацией и не проверяется как
доказательство. `settings` содержит все настраиваемые пороги с дефолтными значениями;
Все применимые проверки по умолчанию `required`; `policy` содержит только осознанные
послабления `advisory`/`off`, а `suppress` — именованные исключения с обязательной причиной.
Секция `applicability` позволяет одним ответом выключить семейство проверок, например все
C#-измерения через `{ "csharp": { "applicable": false, "reason": "..." } }`.

В CI это отдельный шаг рядом с тестами:

```yaml
- name: Repository harness
  run: harness check
```

Коды возврата: `0` — всё выбранное прошло, `1` — доказано нарушение, `2` — проверить
достоверно не удалось (сюда же относится отсутствующий или невалидный `.harness.json`).

## Собственные проверки

То, что не воспроизводит чужой пайплайн и что в каждом репозитории расходится:

- maintainability hotspots — размер файлов, типов и методов, ветвление, ширина API;
- не больше одного верхнеуровневого C# `class` или `record` в authored-файле;
- нормализованные межфайловые повторы C#;
- документационная политика: один корневой навигационный документ и симлинки на него.

Специфичные для продукта контракты и архитектурные правила остаются в самом репозитории.
