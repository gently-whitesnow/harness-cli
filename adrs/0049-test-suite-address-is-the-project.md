# ADR-0049: Адрес тестов — проект, а не его файлы

## Status

Accepted. Уточняет форму `paths` из [ADR-0014](0014-frame-answers-are-self-reported.md);
принцип «paths не инспектируются» не меняется.

## Context

ADR-0014 сделал `paths` навигацией: харнес проверяет форму ответа и не ищет адрес в Git.
Ридер принимал любой непустой массив строк, а `harness explain frame.tests.unit` называл
только пример `tests/Unit`. Сравнение двух пилотных репозиториев на контракте 2.10
показало, как это читает агент, заполняющий рамку: один пилот назвал в `tests.unit` два
проекта, другой — 17 отдельных файлов `*Tests.cs` и `*.test.tsx` из трёх проектов, а в
`tests.integration` — файл рядом с проектом. Отчёт печатал «3 адреса and 14 more» и
считал ответ пройденным. Владелец ожидал, что в ответе называют проект с юнитами.

Причина в самом контракте: харнес объясняет через ошибки, а здесь ошибки не было. Текст
«navigation addresses» честно позволяет перечислить всё найденное, и перечень файлов
устаревает с первым новым тестом.

Обсуждались альтернативы:

- **Проверять, что адрес — каталог, по tracked-дереву.** Это инспекция `paths`, которую
  ADR-0014 убрал сознательно; форма ответа должна судиться по самому ответу.
- **Только текст в `explain`.** Агент читает подсказку один раз и не получает сигнала,
  когда перечисляет файлы; пилот это показал.
- **Ограничение только на число адресов.** Ловит инвентарь на любом языке, но пропускает
  пять файлов одного проекта; нужно и правило о форме адреса.

## Decision

1. **Адрес теста — проект.** Для `tests.unit` и `tests.integration` каждая запись `paths`
   называет тестовый проект: его каталог или project file. Запись с суффиксом исходника,
   который харнес читает (`.cs`, `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`,
   `.cjs`), делает вопрос `Incomplete`; отчёт перечисляет найденные файлы и печатает
   готовый массив их каталогов. `tests.architecture` не затронут: единственный файл с
   правилами слоёв или `steiger.config.js` — нормальная навигация.
2. **Навигация — не более пяти адресов.** Для любого вопроса рамки `paths` длиннее пяти
   записей — `Incomplete`: перечень содержимого сворачивается до проектов или каталогов.
3. **Форма судится по строке.** Харнес по-прежнему не ищет адрес в Git и не читает по
   нему; правило видит только текст ответа. Проект, смешивающий виды тестов, отвечает
   `present` с причиной, как и раньше.
4. **Миграция.** Контракт `2.11.0`; маршрут `harness upgrade` называет правило. Ответы
   с файлами станут `Incomplete` до сворачивания к проектам.

## Consequences

### Positive

- Агент, перечисливший файлы, получает ошибку с готовым исправлением вместо `passed`.
- Ответ про тесты перестаёт устаревать с каждым новым тестовым классом.
- `explain frame.tests.unit` и `frame.tests.integration` называют форму адреса явно.

### Negative / Risks

- Список суффиксов ограничен языками, которые читает харнес; файлы других языков ловит
  только предел в пять адресов.
- Пилот с 17 файлами и любой другой репозиторий с таким ответом обязан переписать
  `tests.unit` при `harness upgrade`; в предложенном массиве каталогов для файлов из
  подкаталогов проекта будет подкаталог, а не корень проекта — его выбирает автор.
