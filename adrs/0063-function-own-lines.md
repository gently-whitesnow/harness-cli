# ADR-0063: собственные строки функций

Status: Accepted. Контракт 3.5.0. Возвращает измерение размера функций после
[ADR-0032](0032-topology-over-thresholds.md).

## Context

С контракта 2.0 функции не измеряются. Прежний порог `methodLines` смешивал
регистрацию, таблицы данных, многострочные строки и предметную логику и не
отделял вложенные лямбды. Отказ от размера файла и числа ветвей сохраняется:
ни один из этих сигналов не указывает на один способ исправления.

## Decision

`functions.csharp` и `functions.go` входят в требуемую рамку при наличии
соответствующего языка. `settings.functions.<language>.ownLines` — положительное
число, по умолчанию 80. Проверка считает непустые физические строки без
комментариев от заголовка до закрывающей скобки, исключая вложенные функции,
литералы данных и многострочные строки. Лямбда, локальная функция и Go
func-литерал — самостоятельные единицы. Top-level C# и Go main измеряются.
Тестовый код подчиняется той же норме; исключений по путям нет.

В находке видны собственные и общие логические строки, а также размер самой
крупной вложенной единицы. Исправление — извлечь именованный шаг логики,
достаточно private-метода в том же файле. Правка порога возможна только
изменением tracked `.harness.json`, но не предлагается как исправление находки.

Границы устанавливаются по скобкам после маскирования комментариев и строк,
без компилятора и дополнительных зависимостей, чтобы сохранить NativeAOT.
EF-миграция определяется как generated по синтаксису и исключается общим
ридером C#.

## Consequences

Склейка нескольких утверждений в одну строку остаётся обходом физической
метрики; форматтеры и review отслеживают такие изменения. Если обход начнёт
появляться, отдельное решение может добавить нормализованные own-токены.

TypeScript следует отдельным этапом после общего языкового ридера issue #58.
JSX-разметку следует измерять; стартовый порог для TSX — 150, чтобы длинные
компоненты становились видимы. Это решение о метрике, не введённый здесь
TypeScript-гейт.
