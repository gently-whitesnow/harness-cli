# ADR-0001: Скомпилированный CLI — единственный тестовый шов

## Status

Accepted

## Context

Решение принято в дизайн-сессии до появления реализации CLI. Пользователь явно подтвердил
один приёмочный шов: тест запускает скомпилированный `harness check` на fixture-репозитории
и читает код возврата, консольный отчёт, выбор гейтов, timings и состояние tracked-файлов.
Это тот же интерфейс, которым должны пользоваться человек, агент и позже CI.

Пользователь не задавал отдельный внутримодульный контракт: подтверждён был именно внешний
шов. Техническая альтернатива через `InternalsVisibleTo` или публичные типы дала бы более
быстрые тесты, но сделала бы устройство `Checks/`, `Engine/` и `Git/` частью тестового
контракта ещё до того, как форма этих модулей устоялась.

## Decision

`tests/Harness.Tests` гоняет скомпилированный исполняемый файл и проверяет его stdout и код
возврата. Internal-типы не становятся `public` только ради тестируемости.

## Consequences

### Positive

- Текущий test project ссылается на CLI с `ReferenceOutputAssembly=false`: ссылка только
  строит executable, а тесты взаимодействуют с ним через отдельный процесс.
- NativeAOT smoke test гоняет тот же `check` на passing и failing repository fixture, а не
  отдельный упаковочный интерфейс.
- Изменение внутренней структуры не требует нового публичного интерфейса ради тестов.

### Negative / Risks

- Каждый сценарий платит за запуск процесса; NativeAOT-сценарий дополнительно платит за
  публикацию, поэтому такой набор заведомо дороже in-process unit tests.
- Ошибка локализуется сначала по наблюдаемому отчёту. Если нужная диагностика не видна через
  CLI, приходится улучшать интерфейс или исследовать implementation без отдельного тестового
  контракта на internal-типы.
