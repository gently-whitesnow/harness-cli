# ADR-0056: Рамка для конфигурационных репозиториев — комментарии YAML по позиции, файлы вне осей, подсказки init

## Status

Accepted. Развивает [ADR-0043](0043-comment-density-across-languages.md) (плотность
комментариев в YAML), [ADR-0054](0054-explicit-only-frame.md) (`harness.coverage`, детекция
осей) и [ADR-0055](0055-go-language-axis.md) (исключение doc-комментариев по позиции,
подсказка init про toolchain). Контракт 3.2 вместе с [ADR-0057](0057-ansible-axis.md).

## Context

Контракт 3.1 калиброван на репозиториях прикладного кода: C# и Go с YAML и TypeScript
рядом. Пилот на инфраструктурном репозитории — Ansible-конфигурация одного VPS, ~30 tracked
YAML-файлов (playbook, роли, `group_vars`), пять Jinja-шаблонов, один Python-скрипт,
ini-inventory, `Makefile`, несколько Markdown-документов в `docs/`; CI гоняет
`ansible-playbook --syntax-check`, `ansible-lint` и сверку сгенерированного Markdown с
`group_vars` — показал, что рамка 3.1 после `init` (детектируется только ось `yaml`) дала бы:

| Проверка | Итог | Причина |
|---|---|---|
| `comments.yaml` 10/8 | FAIL, 5 файлов из 29 | `group_vars/all/*.yml` и playbook: 24–46% строк с комментарием — документация схемы (что означает ключ, почему значение такое), не «параллельный нарратив» |
| `docs.policy` | FAIL | нет `AGENTS.md`/`CLAUDE.md`; сгенерированный и рукописные документы в `docs/` — «прочий Markdown» |
| `harness.coverage` | PASS, но дыра | `.py`, `.j2`, `.ini`, `Makefile` не принадлежат ни одной оси; coverage судит оси, а не файлы — риск, названный в ADR-0054 |
| `frame.*`, `commits`, `verify` | ложатся без доработок | `make syntax/lint/docs-check` — готовые адреса для `answers.build/lint/tests` |

Формула ADR-0043 предполагает код, который может «объяснить себя именами»: в C#
комментарий над полем чаще всего пересказывает имя. В `group_vars` имени недостаточно —
комментарий рядом с ключом единственное место, где записана схема, и ридер `YamlCommentLines`
считал его наравне с прозой внутри задачи, включая trailing-комментарий на строке значения.

Обсуждались альтернативы. Для комментариев: (a) исключить по позиции только блок над
top-level ключом или элементом top-level списка — по образцу `comments.go`; замер на пилоте
показал, что узкое правило не спасает ни один из пяти файлов (самый плотный файл каталога
сервисов остаётся на 32,5%, с допуском пустых строк между блоком и ключом — на 14,8%),
потому что документация схемы стоит над вложенными ключами; (b) отдельный дефолт
`percentageLimit` для YAML; (c) `init` ставит `comments.yaml: advisory`, когда в индексе нет
ни одной оси прикладного языка. Рецензент отдельно просил зафиксировать калибровку правила
числами, а не ожиданием. Для документации обсуждалась форма ответа `answers.docs.generated`,
выводящая сгенерированный Markdown из `docs.policy`; рецензент назвал её адресным
исключением по поведению (ADR-0035), и владелец отказался от генерируемого Markdown в
репозитории — сценарий отклонён, `docs.policy` не меняется. Для файлов вне осей: новая ось
«прочее», находка `coverage` на неизвестный суффикс, строка verbose details.

## Decision

1. **`comments.yaml` исключает документацию по позиции, на любой глубине.** Формула и
   дефолт 10/8 без изменений. Блок подряд идущих строк-комментариев считается документацией
   и выходит из обоих счётчиков, если следующая непустая строка — ключ mapping (`key:`),
   элемент списка (`- `) на любой глубине или `---`; пустые строки между блоком и ключом
   допускаются. Trailing-комментарий на строке со значением (`key: value  # …`) —
   документация значения, строка остаётся authored без комментария. Прозой остаются только
   блоки, за которыми (через пустые строки) идёт другой блок комментариев или конец файла:
   на пилоте это ровно закомментированный конфиг и свободные абзацы. Директивы `# yamllint`,
   `# noqa`, `# ansible-lint` — код, как директивы Go. Вариант (b) отклонён: поднятый порог
   разрешил бы столько же прозы в задачах ролей; предел остаётся одним для всех языков.
   Калибровка на пилоте: все шесть файлов с ≥10 комментариями проходят (самый плотный
   файл доступа — 7 строк прозы из 98 authored, остальные — 0). `explain comments.yaml`
   называет false positive: закомментированный конфиг непосредственно над ключом проходит
   как документация, и правило не отличает схему от пересказа имени.
2. **`init` пишет `comments.yaml: advisory` для рамки без оси прикладного языка** — пока в
   индексе (или в уже объявленной `applicability`) нет `csharp`, `go` или `typescript`.
   Правило п. 1 калибровано на одном репозитории; конфигурационный репозиторий получает
   видимую, но не блокирующую находку, а возврат к `required` — отдельным ADR по данным
   нескольких пилотов. Тот же дефолт печатают фрагменты `harness.coverage` и `upgrade`;
   существующая явная policy при `upgrade` не переписывается (ADR-0045).
3. **Файлы вне осей печатаются в details `harness.coverage`.** Одна строка verbose details:
   `sources of no axis: .j2 5, .ini 1, .py 1, no suffix 1` — суффиксы и счёт, отсортированные
   по счёту убыв., затем по имени; без имён файлов; вне generated/vendored-каталогов
   (как `FrameAxis.Detect`); файлы осей, Markdown (`docs.policy`) и dot-файлы не считаются.
   Это не находка и не меняет исход: coverage по-прежнему судит оси. Ось «прочее» отклонена:
   у неё нет проверок; находка на неизвестный суффикс — потому что список известных суффиксов
   не бывает полным и каждый vendored-файл дал бы blocking.
4. **`init` при обнаруженной оси `ansible` печатает подсказку про toolchain** по образцу п. 5
   ADR-0055: `answers.lint` — место запуска `ansible-lint` и `yamllint`, `answers.build` —
   `ansible-playbook --syntax-check`, `answers.tests.integration` — molecule; `explain`
   вопросов `frame.lint`, `frame.build` и `frame.tests.integration` повторяет её. Харнес
   ничего из этого не запускает (ADR-0011).
5. **Не делается.** `answers.docs.generated` и любое третье имя документа для `docs.policy`
   (адресное исключение, ADR-0035/0025); запуск или чтение отчётов `ansible-lint`/`yamllint`;
   ось для `.j2`/`.ini`/`Makefile`. Проверки, специфичные для Ansible, — ADR-0057.
6. **Контракт — minor (3.2).** Уточнение счёта и дефолта init; рамки без YAML-комментариев
   над ключами не меняют исход, существующие явные policy не переписываются.

## Consequences

### Positive

- На пилоте после п. 1 `comments.yaml` проходит без изменения предела: превышение давали
  только блоки над ключами `group_vars` и playbook; отдельного порога для «документирующих»
  языков не появляется.
- Одна формула комментариев на все языки и одно правило исключения по позиции для Go и YAML;
  разница — только в том, что YAML-ключ бывает на любой глубине.
- Дыра coverage, названная в ADR-0054, стала видимой строкой отчёта без новой находки.

### Negative / Risks

- Исключение по позиции не различает схему, пересказ имени и закомментированный конфиг над
  ключом: блок над ключом не считается, даже если бесполезен; предел проверяет только прозу,
  за которой нет ключа. Принято ради одного предела для всех языков.
- Списки «прикладных» осей для п. 2 и суффиксов, исключённых из п. 3, — таблицы в коде; новая
  ось правит обе, что защищает тест реестра, а не контракт.
- Калибровка — один конфигурационный репозиторий; `advisory` по п. 2 — цена этой выборки.
