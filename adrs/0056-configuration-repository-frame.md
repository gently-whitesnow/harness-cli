# ADR-0056: Рамка для конфигурационных репозиториев — комментарии, generated docs, файлы вне осей

## Status

Proposed. Развивает [ADR-0043](0043-comment-density-across-languages.md) (плотность
комментариев в YAML), [ADR-0010](0010-documentation-policy.md) и
[ADR-0025](0025-nested-agent-documents.md) (политика Markdown) и
[ADR-0054](0054-explicit-only-frame.md) (`harness.coverage`). Код не реализован;
принятие — minor-релиз контракта 3.x.

## Context

Контракт 3.1 калиброван на репозиториях прикладного кода: C# и Go с YAML и TypeScript
рядом. Пилот на инфраструктурном репозитории — Ansible-конфигурация одного VPS, ~30 tracked
YAML-файлов (playbook, роли, `group_vars`), пять Jinja-шаблонов, один Python-скрипт,
`inventory.ini`, `Makefile`, пять Markdown-документов в `docs/`; CI гоняет
`ansible-playbook --syntax-check`, `ansible-lint` и проверку «сгенерированный
`docs/ARCHITECTURE.md` совпадает с `group_vars`» — показал, что рамка 3.x после `init`
(детектируется только ось `yaml`) дала бы:

| Проверка | Итог | Причина |
|---|---|---|
| `comments.yaml` 10/8 | FAIL, 5 файлов из 29 | `group_vars/all/*.yml` и playbook: 24–46% строк с комментарием — документация схемы (что означает ключ, почему значение такое), не «параллельный нарратив» |
| `docs.policy` | FAIL | нет `AGENTS.md`/`CLAUDE.md`; сгенерированный `docs/ARCHITECTURE.md` с CI-гейтом актуальности и три рукописных гайда в `docs/` — «прочий Markdown» |
| `harness.coverage` | PASS, но дыра | `.py`, `.j2`, `.ini`, `Makefile` не принадлежат ни одной оси; coverage судит оси, а не файлы — риск, названный в ADR-0054 |
| `frame.*`, `commits`, `verify` | ложатся без доработок | `make syntax/lint/docs-check` — готовые адреса для `answers.build/lint/tests` |

Формула ADR-0043 предполагает код, который может «объяснить себя именами»: в C#
комментарий над полем чаще всего пересказывает имя. В `group_vars` имени недостаточно —
комментарий рядом с ключом единственное место, где записана схема, и ридер `YamlCommentLines`
считает его наравне с прозой внутри задачи. Причём считается любая строка с `#` после
пробела, включая trailing-комментарий на строке значения.

Обсуждались альтернативы. Для комментариев: (a) исключить из счёта по позиции блок
комментариев непосредственно над top-level ключом или элементом списка — по образцу
`comments.go` (ADR-0055 п. 1); (b) отдельный дефолт `percentageLimit` для YAML; (c) `init`
ставит `comments.yaml: advisory`, когда в индексе нет ни одной оси прикладного языка.
Для документации: glob-исключения путей в `settings`, «любой файл под `docs/`» разрешён,
новая форма ответа рамки `answers.docs.generated`. Для файлов вне осей: новая ось
«прочее», находка `coverage` на неизвестный суффикс, строка verbose details.

## Decision

1. **`comments.yaml` исключает doc-комментарии по позиции.** Формула и дефолт 10/8 без
   изменений; из счёта комментариев (и из authored-строк) исключается блок строк-комментариев,
   стоящий непосредственно над ключом mapping верхнего уровня документа или над элементом
   top-level списка (`- name:` playbook и task-файлов), как `comments.go` исключает блок над
   top-level декларацией. Trailing-комментарий на строке значения и комментарий внутри
   вложенного mapping — по-прежнему проза. Вариант (b) отклонён: поднятый порог разрешил бы
   столько же прозы в задачах ролей; предел остаётся одним для всех языков. `explain
   comments.yaml` называет false positive: комментарий-«шапка» над ключом, который просто
   пересказывает его имя, не считается и не ловится.
2. **До реализации п. 1 `init` пишет `comments.yaml: advisory`** для рамки без оси прикладного
   языка (`csharp`, `go`, `typescript` в индексе отсутствуют): конфигурационный репозиторий
   получает видимую, но не блокирующую находку. Существующая явная policy при `upgrade` не
   переписывается (ADR-0045). После п. 1 `init` возвращает `required`.
3. **Сгенерированный Markdown объявляется ответом рамки.** Необязательная форма
   `answers.docs.generated: { "paths": ["docs/ARCHITECTURE.md"], "reason": "<команда
   проверки актуальности>" }`: до пяти адресов tracked-файлов, адрес — навигация, не
   доказательство (ADR-0014); харнес не проверяет, что файл сгенерирован и актуален — это
   гейт CI через `answers.verify`. Названные пути `docs.policy` не считает нарушением.
   Остальной `docs/*.md` — по-прежнему нарушение: рукописный гайд переезжает в `AGENTS.md`
   (навигация) или `adrs/` (решение). Glob-исключения отклонены как адресное подавление
   находки (ADR-0035); «любой файл под `docs/`» — как третье имя по каталогу, а не по имени
   (ADR-0025). Путь с суффиксом не `.md` — `Incomplete` с подсказкой формы.
4. **Файлы вне осей печатаются в details `harness.coverage`.** Одна строка verbose details:
   `tracked sources of no axis: .j2 5, .py 1, .ini 1, (no suffix) 1` — суффиксы и счёт,
   без имён файлов, вне generated-каталогов. Это не находка и не меняет исход: coverage
   по-прежнему судит оси. Ось «прочее» отклонена: у неё нет проверок; находка на неизвестный
   суффикс — потому что список известных суффиксов не бывает полным и каждый vendored-файл
   дал бы blocking.
5. **`init` для рамки без прикладной оси печатает подсказку про toolchain** по образцу п. 5
   ADR-0055: `answers.lint` — место запуска `ansible-lint`/`yamllint`, `answers.build` —
   `ansible-playbook --syntax-check`, `answers.tests.integration` — molecule; `explain`
   вопросов `frame.lint`/`frame.build` повторяет её. Харнес ничего из этого не запускает
   (ADR-0011).
6. **Не делается.** Запуск или чтение отчётов `ansible-lint`/`yamllint`; проверка
   актуальности сгенерированного файла харнесом (это запуск генератора, ADR-0011); третье
   имя документа для `docs.policy`; ось для `.j2`/`.ini`/`Makefile`. Проверки, специфичные
   для Ansible, — [ADR-0057](0057-ansible-axis.md).
7. **Контракт — minor.** Новая необязательная форма ответа и уточнение счёта; рамки без
   YAML-комментариев над top-level ключами и без `docs.generated` не меняют исход.

## Consequences

### Positive

- Ожидается, что на пилоте `comments.yaml` пройдёт после п. 1 (превышение давали только
  блоки над ключами `group_vars`) и станет advisory до этого по п. 2; `docs.policy` пройдёт
  после `docs.generated` и переноса трёх гайдов в `AGENTS.md`/`adrs/`.
- Одна формула комментариев на все языки и одно правило исключения по позиции для Go и YAML;
  отдельного порога для «документирующих» языков не появляется.
- Дыра coverage, названная в ADR-0054, стала видимой строкой отчёта без новой находки.

### Negative / Risks

- Исключение по позиции не различает схему и пересказ имени: блок над ключом не считается,
  даже если он бесполезен; предел проверяет только прозу внутри значений.
- `docs.generated` — self-reported: харнес поверит, что файл сгенерирован, без гейта в CI
  путь просто исключает документ из политики. Принятая цена той же модели, что `answers.*`.
- Списки «прикладных» осей для п. 2 и суффиксов для п. 4 — таблицы в коде; новая ось
  правит обе, что защищает тест реестра, а не контракт.
- Пилот один; калибровка на нескольких конфигурационных репозиториях не проводилась.
