# ADR-0038: Плоская директория из 20+ файлов получает advisory о группировке

## Status

Accepted. Дополняет конвенции `sliced-dotnet/1` из
[ADR-0033](0033-canonical-standard-over-declarations.md) неблокирующим сигналом.

## Context

Steiger на commit `e21b75e71dc9a7805f9045d3a29c01566167e1c2` реализует правило
`fsd/shared-lib-grouping`: каталог `shared/lib` с более чем `THRESHOLD = 15`
непосредственными детьми получает диагностику «Consider grouping them». Правило считает
детей каталога любого вида — и файлы, и уже созданные подгруппы-каталоги — и действует
только в одной точке стандарта FSD.

В sliced-dotnet нет выделенного `shared/lib`, но наблюдаемая проблема та же и не привязана
к одному каталогу: любой каталог architecture-zone, в котором непосредственный список
`.cs`-файлов перестал читаться целиком, скрывает несколько назначений в одном bucket.
Проверка `architecture.sliced-dotnet` уже печатает похожий сигнал для слайсов
(`excessive-slicing`, порог 20 ungrouped-слайсов) как advisory-observation, которую никакая
policy не превращает в blocking; тот же прецедент задан `insignificant-slice`.

## Decision

1. `architecture.sliced-dotnet` печатает advisory-observation `flat-directory-grouping` для
   каждого каталога внутри architecture-zone на любой глубине, в котором непосредственно
   (не рекурсивно) лежит 20 и более authored `.cs`-файлов.
2. Считаются только исходники: файлы с суффиксами `*.g.cs`, `*.generated.cs`,
   `*.designer.cs` и placeholder-файлы не учитываются — тем же суждением, что у C#-ридера.
   Подкаталоги не считаются: их наличие — уже начатая группировка, но она не оправдывает
   плоский список рядом.
3. Порог — 20 файлов, а не буквальные 15 Steiger. Steiger считает детей всех видов в одной
   точке иерархии; здесь считаются только файлы, а C#-конвенция «один тип — один файл»
   (проверка `types-per-file.csharp`) даёт больше файлов на тот же объём кода, чем модуль
   JS. Порог согласован с `excessive-slicing`: каталог из 10–15 файлов остаётся тихим,
   каталог из 20+ получает сигнал.
4. Сигнал — observation-строка `advisory <путь>: flat-directory-grouping: ...`, а не
   `Finding`: по ADR-0002 у эвристики о читаемости списка нет универсального blocking
   remediation, поэтому она не меняет код возврата ни при какой policy, включая
   `required`. Смягчается или выключается только вся проверка целиком.

## Consequences

### Positive

- Каталог, накопивший десятки несгруппированных файлов, становится видимым в каждом
  отчёте до того, как превратится в необозримую свалку.
- Правило детерминировано по tracked-дереву, не требует C#-графа и предлагает локальное
  исправление: сгруппировать файлы по назначению.

### Negative / Risks

- Порог — соглашение, а не измерение: каталог из 19 связанных по смыслу файлов и каталог
  из 19 случайных файлов неотличимы для правила. Ожидается, что часть сигналов останется
  сознательно непринятой; observation это допускает без давления на код возврата.
- Группировка ради порога может дать формальные подкаталоги без смысла; правило не
  проверяет качество имён новых групп — за словарь отвечает
  [ADR-0040](0040-zone-wide-vocabulary.md).
