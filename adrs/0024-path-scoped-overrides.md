# ADR-0024: Path-scoped override — норма зоны, а не исключение из находки

## Status

Accepted. Опирается на [ADR-0013](0013-a-named-exception-is-written-down-and-printed.md)
(исключение именуется и обосновывается), [ADR-0017](0017-required-by-default.md) (policy
хранит только послабления) и [ADR-0023](0023-release-version-as-the-verification-contract.md)
(релиз — контракт проверки).

## Context

Блокер миграции репозитория services-platform: его самописный
`.quality/maintainability-budget.json` задаёт разные числовые лимиты разным зонам кода.
Реальные зоны оттуда: Kubernetes-адаптер с watch/reconnect-логикой живёт с `methodLines
120` и `branches 25`; REST-контроллеры — с `constructorParameters 15` и `publicMembers 20`;
Mongo-мапперы — с `publicMembers 30`; тестовые файлы — со своими ослабленными лимитами;
каталог Domain исключён из size-бюджета целиком. Отдельно `duplication`: сгенерированные
Mongo-модели, мапперы и тесты несут легализованные повторы и шумят в отчёте.

Существующие механизмы это не выражают. `settings` — один набор чисел на весь репозиторий.
`policy: off/advisory` — на всю проверку, после чего долг в остальном коде перестаёт быть
виден. `suppress` принимает конкретную находку по адресу: он подходит для «этот файл плох
исторически», но не говорит «в этой зоне другая норма» — подавленная находка печатается
каждый прогон как принятый долг, хотя владелец зоны долгом её не считает.

Обсуждались две формы: погрузить пер-зонные числа внутрь `settings` каждой проверки или
завести отдельную секцию по образцу `suppress`. Владелец задачи явно потребовал «glob →
свои пороги или off, с обязательным reason» и разграничения с `suppress`.

## Decision

В `.harness.json` появляется верхнеуровневая секция `overrides` — список записей вида:

```jsonc
"overrides": [
  { "check": "maintainability.csharp", "paths": ["src/**/Kubernetes/**"],
    "reason": "watch/reconnect-логика адаптера", "settings": { "methodLines": 120 } },
  { "check": "duplication.csharp", "paths": ["src/**/Mongo/**", "tests/**"],
    "reason": "легализованные повторы моделей и тестов", "off": true }
]
```

Запись называет ровно одну проверку (`check`), непустой список glob-путей (`paths`),
непустой `reason` и ровно одно из двух действий: `settings` — частичная перенастройка
чисел этой проверки для совпавших путей, либо `"off": true` — файлы зоны исключаются из
анализа этой проверки. Любое отступление от формы — включая пустой или отсутствующий
`reason` — делает конфиг невалидным: прогон завершается `Incomplete`, код `2`, с сообщением,
называющим ключ.

Override применим только к path-scoped проверкам, где субъект измерения живёт в файле:
`comments.csharp`, `maintainability.csharp`, `cohesion.csharp` принимают `settings` и `off`;
`types-per-file.csharp` и `duplication.csharp` — только `off`, потому что настроек у них
нет. Ключи `settings` в записи валидируются тем же словарём, что и глобальная секция
`settings` этой проверки. `dependencies.csharp` не принимает override: его субъект — ребро
между модулями, у которого нет одного пути.

Glob сравнивается с repository-relative путём tracked-файла: `*` и `?` — внутри сегмента,
`**` — ноль и более сегментов. Эффективные числа файла — глобальные `settings` проверки,
поверх которых в порядке объявления ложатся `settings` каждой совпавшей записи; `off`
действует, если совпала хоть одна off-запись, независимо от порядка.

Разграничение с `suppress` фиксируется так: **suppress принимает находку, override меняет
норму**. Suppress остаётся точечным принятием конкретного нарушения — движок применяет его
после `Evaluate`, находка печатается строкой `suppressed`, а протухшая становится
advisory-находкой. Override действует до измерения: он меняет сравнительную точку или
состав анализируемого, поэтому живёт там же, где `settings`, — внутри проверки, и не
порождает ни строк в отчёте, ни staleness-находок. Норма зоны законна и тогда, когда в зоне
сейчас нет ни одного превышения; «протухнуть» ей нечем. Дисциплина ADR-0013 «проверка не
знает про исключения» не нарушается: проверки и раньше читали свои настройки.

По ADR-0023 секция входит в контракт релиза `1.1.0`: конфиг с `overrides` при пине ниже
требует поднять пин через `harness upgrade` и завершает прогон кодом `2`. Бинарь `1.0.0`
на таком конфиге отвергает неизвестный ключ — тоже `2`, поэтому вердикт не зависит от
версии бинаря, а само появление секции — tracked-правка, видимая на ревью.

## Consequences

### Positive

- Все зоны services-platform выражаются штатным конфигом: смягчённые лимиты по glob для
  maintainability, `off` для duplication в сгенерированных зонах — и самописный бюджет
  становится не нужен.
- Долг вне переопределённых зон остаётся виден: норма меняется для зоны, а не для проверки.
- Отчёт продолжает печатать честные числа: находка в зоне сравнивается с её эффективной
  сравнительной точкой, и именно эта точка стоит в строке отчёта.
- `reason` обязателен и попадает в diff — у каждой зоны есть записанное обоснование.

### Negative / Risks

- Off-зона исчезает из отчёта молча: в отличие от `suppressed`-строк, исключённые файлы не
  печатаются. Принятая цена — обоснование живёт в tracked-конфиге, а не в каждом прогоне.
- Override не «протухает»: запись с glob, которому больше ничего не соответствует, никак
  не подсвечивается. Симметричный staleness-механизм сознательно не заводится — норма зоны
  не обязана ловить нарушения, чтобы оставаться нормой.
- `settings` в override может и ужесточить числа, не только ослабить: это симметрично
  глобальным `settings`, которые репозиторий и так контролирует.
- Матчер глобов — собственный: BCL-вариант не знает `**`. Он ограничен тремя
  метасимволами и покрыт приёмочными тестами, но остаётся ещё одним куском кода на
  поддержке.
