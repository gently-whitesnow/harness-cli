# ADR-0020: Контракт сообщений коммитов и явная подготовка клона

## Status

Accepted. Точечно уточняет [ADR-0008](0008-the-harness-only-observes.md) и
[ADR-0011](0011-the-harness-does-not-run-the-repository-toolchain.md): `check` остаётся
наблюдающим, а явные `init` и `setup` могут менять только локальную Git-конфигурацию и
файлы внутри Git metadata, но не tracked-контент репозитория.

## Context

Единый формат полезен до появления коммита: ошибка в CI уже попала в историю ветки и
требует amend/rebase. Git вызывает `commit-msg` с окончательным текстом до записи объекта,
но hooks не клонируются и tracked-репозиторий не может безопасно активировать исполняемый
код сам. Особенно часто одноразовый setup теряется у агентов и в одноразовых песочницах.

Conventional Commits задаёт машинную строку `type(scope): description`, но не обеспечивает
содержательный body. Для этого инструмента важен контекст решения: diff показывает «как»,
а сообщение должно сохранять «почему», выбранное решение, границы и последствия.

## Decision

`.harness.json` принимает `settings.commits.language` (`en` или `ru`) и
`settings.commits.requireSetup`. Машинные type, scope и trailers остаются английскими;
человеческие description, заголовки секций и текст следуют выбранному языку.

`harness setup` идемпотентно создаёт managed `commit-msg` и commit template внутри Git
metadata текущего клона, затем задаёт локальные `core.hooksPath` и `commit.template`. Он не
заменяет чужие значения или unmanaged-файлы. `harness init` создаёт настройку с
`requireSetup: true` и сразу готовит текущий клон; каждый следующий клон запускает `setup`
отдельно.

`commits.setup` — blocking-проверка, когда `requireSetup` true. Она сверяет локальные
настройки, managed hook, исполнимость и шаблон выбранного языка. Исправление одно:
`harness setup`. Старые frames без opt-in остаются `NotApplicable`.

Валидатор принимает Conventional header с фиксированными типами и kebab-case scope.
Заголовок длиннее 72 символов, точка в конце, неверный язык и нарушенная структура —
blocking. Длина 51–72 и строки body длиннее 72 — advisory: это полезная норма чтения, но
URL и технические идентификаторы делают жёсткий перенос ложноположительным.

Body необязателен для атомарного очевидного изменения. Нетривиальный body обязан иметь
непустые локализованные секции Context/Контекст и Decision/Решение; Boundaries/Границы,
Consequences/Последствия и Git trailers опциональны. `BREAKING CHANGE` не переводится.

Hook допускает временные `fixup!`/`squash!`, а `harness commits check <base>..<head>`
запрещает их в публикуемом диапазоне. Стандартные Git merge/revert subjects принимаются.

## Consequences

- Ошибка объясняется до создания коммита тем же валидатором, который использует CI.
- Пропущенный setup виден в обычном `harness check`, а не обнаруживается случайно позже.
- Hook можно обойти через `--no-verify`, поэтому окончательный enforcement принадлежит
  явной range-проверке CI.
- Смена языка или расположения бинарника делает setup stale; повторный `harness setup`
  безопасно обновляет managed-файлы.
- Язык body не определяется эвристически: технические термины закономерно смешиваются.
  Blocking-проверка языка относится только к description.
