# ADR-0041: Слой — это сборка

## Status

Accepted. Ужесточает инварианты `sliced-dotnet/1` из
[ADR-0033](0033-canonical-standard-over-declarations.md).

## Context

Стандарт до сих пор судил только дерево каталогов и лексический C#-граф. Раскладку сборок он
не видел, и первый внешний потребитель показал легальную дыру: composition root компилировал
чужие слои через linked-компиляцию — `<Compile Include="../Api/**/*.cs" />` — и весь «DAG
слоёв» существовал лишь в отчёте харнеса. Компилятор границы не держал: любой файл видел
internal-типы всех подключённых слоёв, ссылка вверх ловилась только прогоном харнеса, а
misconfigured IDE или новый проект легко возвращали монолит.

В .NET у слоя есть естественная физическая граница — assembly. Когда каждый слой собирается
собственным проектом, направление зависимостей держит сам компилятор: недопустимая ссылка не
компилируется, `internal` действует на границе слоя, а ProjectReference-граф читается в
ревью как таблица слоёв. Прецедент чтения tracked project XML без MSBuild evaluation задан
проверками ADR-0019.

Альтернатива — оставить раскладку сборок конвенцией — обсуждалась и отклонена: ADR-0032
называет необязательную декларацию точкой гибкости, а здесь гибкость означает, что весь
ярус 1 можно обойти одним `Compile Include`.

## Decision

`architecture.sliced-dotnet` получает инварианты «слой = сборка», blocking наравне с
остальными инвариантами яруса 1:

1. **Один проект на слой.** Канонический слой-каталог зоны, содержащий authored `.cs`-файлы,
   обязан содержать ровно один tracked `*.csproj` (`layer-project-missing`,
   `layer-project-count`). Слайсы внутри слоя проектами не становятся: их границы продолжает
   держать харнес по лексическому графу.
2. **Проект компилирует только свой слой.** Литеральный `Compile Include`, чей
   нормализованный путь выходит за пределы слоя проекта, — linked-компиляция чужого слоя и
   blocking-находка `linked-compilation`; замена — ProjectReference на проект владеющего
   слоя.
3. **ProjectReference — по таблице слоёв.** Ребро между проектами одной зоны обязано входить
   в таблицу разрешённых рёбер ADR-0033/0036 (`Host` → все; `Api`, `Consumers`,
   `Infrastructure` → `Application`, `Domain`, `Shared`; `Application` → `Domain`, `Shared`;
   `Domain` → `Shared`; `Shared` → ничего). Ребро в другую зону запрещено. Проект внутри
   зоны, лежащий вне канонического слоя, — `project-outside-layer`.
4. **Только tracked XML.** Проверка объявляет `*.csproj` в `Evidence` (ADR-0026) и читает
   его тем же способом, что проверки ADR-0019; MSBuild evaluation не выполняется, поэтому
   item-пути с MSBuild-свойствами (`$(...)`) не оцениваются и не судятся. Ссылка на проект
   вне всякой зоны (общая библиотека репозитория) стандартом v1 не судится.
5. **Гейт применимости.** Репозиторий без единого tracked SDK-style `*.csproj` не имеет
   раскладки сборок, которую можно судить, — инварианты молчат, остальная проверка формы
   действует как раньше.

Это новый обязательный инвариант контракта — ломающий для репозиториев с linked-раскладкой,
поэтому релиз поднимает минорную версию до 2.5.0, и `harness upgrade` печатает миграцию
блоком «Release 2.5 additions». Имя стандарта остаётся `sliced-dotnet/1`: ADR-0033 всегда
описывал слои как единицы зависимости, здесь их граница становится доказуемой.

## Consequences

### Positive

- Направление зависимостей между слоями держит компилятор, а не только прогон харнеса;
  `internal` впервые действует на границе слоя.
- ProjectReference-граф зоны совпадает с таблицей слоёв и читается в ревью без деклараций.
- harness-cli сам подпадал под инвариант (один `.csproj` на всю зону) и мигрировал на
  проект-на-слой в этом же релизе, чтобы собственный гейт не оставался красным.

### Negative / Risks

- Ломающий сдвиг: репозиторий с linked-компиляцией обязан физически разделить проекты,
  прежде чем гейт снова станет зелёным; полуавтоматической миграции нет.
- Без MSBuild evaluation include с `$(...)` остаётся слепым пятном — осознанная цена
  ADR-0019; generated-код и динамические item-группы не судятся.
- Больше проектов — больше файлов сборки и чуть дольше restore; для NativeAOT-публикации
  значим только entry-проект `Host`.
