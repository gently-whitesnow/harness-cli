# ADR-0003: Шесть исходов проверки и три кода возврата

## Status

Accepted

## Context

В дизайн-сессии пользователь отдельно развёл три ситуации: доказанное нарушение, отсутствие
quality capability и невозможность достоверно проверить. В частности, необнаруженные
architecture tests не должны становиться error: без manifest харнес может утверждать лишь,
что не нашёл известную evidence. При этом отсутствующий SDK или повреждённый execution plan
нельзя показывать как зелёный результат.

Пользователь подтвердил контракт `0/1/2` для будущего CI, но v0 остаётся локальным
помощником. Поэтому внутренний outcome должен быть богаче process exit code и сохраняться в
читаемом отчёте.

## Decision

`CheckOutcome` — шесть значений: `Passed`, `Failed`, `Skipped`, `NotApplicable` (нет стека,
о котором проверка), `ReadinessGap` (стек есть, объявленной команды качества нет),
`Incomplete` (достоверно проверить не удалось).

Отображение в коды возврата (`Engine/GateEngine.cs`): `Incomplete` в любом гейте → `2`;
иначе `Failed` → `1`; иначе `0`. `NotApplicable` и `ReadinessGap` код не меняют — это не
нарушения. Заголовок отчёта их различает: `PASS`, `PASS WITH GAPS`, `NOTHING VERIFIED`,
`FAIL`, `INCOMPLETE`.

## Consequences

### Positive

- Приёмочные тесты подтверждают, что недостоверный прогон поднимает `2`, доказанное
  нарушение — `1`, а gaps и advisory findings не подменяются failure.
- Приёмочный сценарий, где все гейты skipped, печатает `NOTHING VERIFIED`, а не `PASS`.
- Отсутствующий stack и отсутствующая quality command остаются разными фактами, хотя оба не
  меняют exit code.

### Negative / Risks

- CI, различающий только `0` и `не 0`, теряет разницу между `1` и `2`.
- `ReadinessGap` не влияет на код возврата, поэтому пробел может жить в отчёте бесконечно.
- Exit code `0` не означает «репозиторий полностью готов»: вызывающий обязан читать
  `PASS WITH GAPS` и `NOTHING VERIFIED`, если полнота доказательств для него существенна.
