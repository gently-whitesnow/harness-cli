# ADR-0069: XML-документация C# не входит в плотность комментариев

## Status

Date: 2026-10-13
Accepted. Контракт 3.9.3. Уточняет [ADR-0015](0015-comment-density-is-a-blocking-source-policy.md)
и [ADR-0028](0028-recalibrated-csharp-defaults.md): `///` над декларацией больше не считается
в `comments.csharp`; исключение по позиции повторяет [ADR-0055](0055-go-language-axis.md).

## Context

ADR-0015 считал `//`, `///` и `/* */` одинаково, а ADR-0028 признал риск: лимит 8 % потребует
именованных исключений для файлов, где плотная документация — часть публичного контракта.
Позже ADR-0035 и ADR-0054 убрали адресное подавление файла, и выхода для такого файла не
осталось, хотя explain сам называет требуемый контракт public API оправданным комментарием.

Противоречие проявилось в пилотном прикладном репозитории со строгой рамкой
(`GenerateDocumentationFile`, warnings-as-errors, CS1591 включён). Слияние тринадцати портов
в три шлюза дало интерфейсы по 9–12 методов. На каждый член компилятор требует `///`, поэтому
однострочный `<summary>` над каждым методом поднимал файл выше 8 %; адаптеры с
`/// <inheritdoc />` на каждом члене — тоже. Проверка подталкивала дробить порт на части
ради счётчика, а не ради смысла: харнес и компилятор требовали несовместимого.

ADR-0055 для Go уже выбрал исключение doc-комментариев по позиции вместо отдельного порога и
прямо назвал цель — один предел для C# и Go, измеряющий прозу, которую автор выбрал написать.
C# в этом решении отставал. Обсуждались альтернативы: исключать только `<inheritdoc />` и
однострочный `<summary>` — граница по содержанию, которую легко обойти переносом строки и
трудно объяснить; читать `GenerateDocumentationFile` из `.csproj` — новое evidence ради той же
границы, а `///` компилятор привязывает к декларации независимо от флага; поднять порог —
разрешить столько же прозы внутри методов.

## Decision

1. **`comments.csharp` считает прозу, а не документацию.** Строки, которые содержат только
   `///`-комментарий и непрерывным блоком стоят непосредственно над строкой кода (член, тип,
   атрибут), выходят из числителя и знаменателя — так, как компилятор привязывает XML-документацию
   к декларации. Формула ADR-0043 и дефолт 10/8 не меняются.
2. **Позиция, не содержание.** Блок `///`, за которым идёт пустая строка, `//`-комментарий или
   конец файла, считается прозой. `////` — обычный комментарий. `/** */` продолжает считаться:
   форма редкая, а различать её по позиции внутри блока — лишняя лексика.
3. **Это исправление 3.9.3.** Новых ключей и секций нет, изменение только убирает находки;
   `harness upgrade` печатает заметку «Release 3.9.3 fixes».

## Consequences

### Positive

- Порт или адаптер с обязательной XML-документацией проходит `required` без дробления на
  файлы и без смягчения policy; предел 8 % измеряет `//` и `/* */` внутри кода.
- C# и Go измеряются одинаково: документация языка вне счёта, проза — в нём.

### Negative / Risks

- Длинный `<remarks>` над приватным членом тоже вне счёта: позиция не различает видимость и
  ценность текста. Пересказ имени в `<summary>` остаётся делом ревью, как в Go.
- `///` внутри тела метода над оператором будет принят за документацию; компилятор
  предупреждает о нём (CS1587), поэтому ожидается, что такие строки редки.
