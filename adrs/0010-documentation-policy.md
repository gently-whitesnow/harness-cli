# ADR-0010: Документационная политика

## Status

Accepted. Рекомендации про `suppress` superseded by
[ADR-0032](0032-topology-over-thresholds.md).

## Context

Пользователь разрешил текстовые инструкции только как навигацию, а не как источник истины:
переиспользуемое правило должно стать гейтом. Долговременное знание разделено между кодом и
тестами (что система делает сейчас), ADR (почему выбрано долгосрочное решение) и историей
task/MR/commit. Постоянную feature specification пользователь исключил из модели.

В дизайн-сессии отдельно подтверждены четыре решения: разрешить короткий root `README.md`,
держать ADR непосредственно в root `adrs/`, ограничить агентскую навигацию 150 строками и
держать один корневой документ под именем `AGENTS.md` — межвендорным именем, которое
агентские инструменты открывают сами, — а `CLAUDE.md` сделать не копией, а прямым symlink
на него. Собственное имя корня вроде `ROOT.md` рассматривалось и отклонено: оно добавляет
имя, которое знает только этот репозиторий, и лишний уровень косвенности. Временная build
spec и tickets жили под `.scratch` и были удалены после реализации; стандартный setup,
создающий `CONTEXT.md` и `docs/agents/*.md`, сознательно не использовался как постоянная
структура этого репозитория.

## Decision

`AGENTS.md` — единственный источник агентской навигации: обычный tracked-файл, не более 150
физических строк. `CLAUDE.md` — прямой относительный симлинк на него: цепочка ссылок, битая
ссылка, абсолютная ссылка и обычный файл различимы, потому что ссылки читаются из индекса
Git. Обратное направление запрещено явно — `AGENTS.md` в роли симлинка даёт нарушение,
иначе корневой текст мог бы уехать в файл, о котором не знает ни одно правило. `README.md` —
краткий обзор. Долговременные решения живут в `adrs/`. Прочий tracked Markdown даёт
blocking-находку. Репозиторий может осознанно смягчить всю проверку через `policy` или
принять конкретный путь через именованный `suppress` с обязательной причиной.

Разделение труда между `AGENTS.md` и `adrs/`: `AGENTS.md` несёт действующее правило в одну
строку со ссылкой на ADR, ADR несёт контекст, решение и последствия. Правило нужно на
каждом шаге и стоит контекста каждый раз, обоснование — один раз, когда правило собираются
изменить.

## Consequences

### Positive

- В текущем Git index `AGENTS.md` — обычный файл, `CLAUDE.md` имеет mode `120000` и цель
  `AGENTS.md`; навигация действительно хранится один раз и под именем, которое агентские
  инструменты читают напрямую.
- Текущий tracked Markdown состоит из `README.md`, `AGENTS.md`, одного symlink и `adrs/`;
  после переноса долговременных решений отдельный каталог `docs/` удалён.
- Длина `AGENTS.md` проверяется исполняемым гейтом, а не договорённостью.

### Negative / Risks

- Политика намеренно opinionated и не описывает все экосистемы: репозиторий с ADR и agent
  skills в других tracked Markdown locations должен настроить `policy` или `suppress`.
- Правило знает ровно два имени: корень и один entry point. Инструмент с третьим именем
  потребует нового решения, а не настройки.
- Симлинк читают не все инструменты. Репозиторий, который держит `CLAUDE.md` файлом-стабом
  со ссылкой на корень, получает от `docs.policy` violation.
- Windows portability симлинков в v0 не решается; первые поддерживаемые среды — macOS и
  Linux.
