# ADR-0014: Ответы рамки self-reported и не проверяются по Git

## Status

Accepted. Заменяет [ADR-0012](0012-declaration-with-an-address-of-proof.md). Правило о
неявной мягкой policy заменено [ADR-0017](0017-required-by-default.md).

## Context

ADR-0012 сделал репозиторий источником ответа о наличии unit-, integration- и architecture
tests, format, lint, build и typecheck, но сохранил за харнесом две проверки правдивости:
адрес должен существовать в tracked Git, а распознанная .NET/web evidence может опровергнуть
отрицательный ответ. На практике первая проверяет только существование пути, не его смысл,
а вторая возвращает каталог эвристик, от которого ADR-0012 пытался отказаться.

Владелец уточнил границу: CLI должна спрашивать, есть ли у репозитория эта инфраструктура;
достаточно ответа в конфиге, факт-чекать его харнес не обязан. Обсуждались удаление вопросов
целиком и сохранение деклараций с Git-доказательством. Вопросы сохранены как общая анкета и
точка policy, а роль доказательства удалена.

## Decision

Tracked `.harness.json` версии 2 содержит полный объект `answers`. Каждый shipped
`frame.<question>` получает ровно один self-reported ответ:

- `paths` — вещь есть; пути служат навигацией для читателя;
- `present: true` + `reason` — вещь есть без одного полезного адреса;
- `present: false` + `reason` — вещи нет;
- `applicable: false` + `reason` — вопрос к репозиторию не относится.

Харнес проверяет JSON-форму и наличие ответа на каждый вопрос. Он не проверяет, существует
ли `paths`, не читает содержимое по адресу, не распознаёт .NET/web machinery и не ищет в Git
противоречия. Репозиторий — единственный источник ответа; ревью отвечает за его честность.

Исходы остаются в словаре ADR-0003:

| Ответ | Исход |
| --- | --- |
| `paths` | `Passed` |
| `present: true` | `Passed` |
| `present: false` | `ReadinessGap` |
| `applicable: false` | `NotApplicable` |
| ответ отсутствует или невалиден | frame `Incomplete` |

`policy: required` на `frame.<question>` превращает `ReadinessGap` от `present: false` в
нарушение. Policy меняет приемлемость ответа, но не включает факт-чек.

## Consequences

### Positive

- Отчёт больше не выдаёт существование tracked-пути за доказательство capability.
- Самодельные и неизвестные харнесу toolchains описываются без каталога пакетов и scripts.
- Удалены .NET/web surfaces, recognized evidence и одностороннее опровержение ответов.
- `paths` остаётся полезным адресом для человека и агента без скрытого обещания проверки.

### Negative / Risks

- Неправдивый положительный ответ проходит; это сознательно оставлено code review.
- Устаревший или ошибочный путь не обнаруживается харнесом.
- Переход меняет schema version, `declarations` на `answers` и selectors с
  `declaration.*` на `frame.*`; конфиги версии 1 требуют явной миграции.
