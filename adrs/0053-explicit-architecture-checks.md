# ADR-0053: Явные архитектурные проверки вместо встроенных advisories

## Status

Date: 2026-09-08
Accepted

Заменяет эвристические рекомендации ADR-0033, ADR-0038, ADR-0039, ADR-0040 и ADR-0051.
Сохраняет доказательные инварианты этих решений и явную policy ADR-0035.

## Context

Владелец потребовал оставлять только проверки, достоверно устанавливающие нарушение
принятого архитектурного правила. `SlicedDotNetShapeCheck` передавал рекомендации через
`Observations`, а движок применял policy только к `Findings`. Поэтому `required` мог
печатать PASS с нулём findings и одновременно список advisory-проблем.

Подсчёт каталогов X в ADR-0039 не доказывает нарушение направления зависимости или
необходимость переноса логики в Domain. Число файлов, отсутствие разрешённого входящего
ребра и сходство имён также не доказывают ошибку архитектуры. Владелец отдельно запросил
индивидуальное отключение доказательных правил на переходный период.

## Decision

Контракт 2.17.0 удаляет категорию `Observations` и следующие эвристики без замены:
`flat-directory-grouping`, `mutual-cross-api`, `cross-api-fan-in`, `directories-by-purpose`,
`insignificant-slice`, `excessive-slicing`, `inconsistent-slice-pluralization`,
`repetitive-naming`, `ambiguous-slice-names`.

Остаются самостоятельные проверки с префиксом `architecture.sliced-dotnet.`:

| Суффикс | Доказуемое правило |
| --- | --- |
| `zone-shape` | Зона существует, канонические и обязательные слои непусты, исходники внутри слоёв |
| `slice-shape` | Слайсы и группы непусты, входные зеркала существуют, нет сирот и файлов вне слайсов |
| `segment-names` | Явный запрещённый словарь в именах слайсов и непосредственных сегментов |
| `layer-assemblies` | Слой = один проект, только свои Compile Include, ProjectReference по таблице слоёв и зон |
| `dependency-direction` | Proven-рёбра не пересекают зоны и соблюдают таблицу слоёв |
| `slice-isolation` | Слайсы одного слоя не импортируют друг друга без явного X |
| `public-api` | Внешний вход в Application-слайс через Contracts, кроме Host; нет Contracts на уровне слоя |
| `cross-api` | X импортируется только адресованным слайсом или Host |

Словарь непосредственных сегментов — принятое правило стандарта, а не вывод о связности
бизнес-логики. Оно остаётся проверяемым запретом; рекомендаций о словаре на иной глубине нет.
Семантика `required/advisory/off` сохраняется: все findings required блокируют, advisory
видны как findings, off отключает целую самостоятельную проверку. Init записывает required
для всех восьми. Группа `architecture.sliced-dotnet` и совместимый селектор `architecture`
выбирают весь набор в `--only`, `--skip`, `explain`. Агрегатной policy больше нет.

`upgrade` копирует прежнее значение policy во все восемь ключей и удаляет старый ключ,
в том числе для rolling `latest`. Некорректное значение или одновременные старый и новые
ключи требуют явного исправления: миграция не перезаписывает выбор пользователя.
Остальные ответы и settings не угадываются; прежние ручные шаги миграций сохраняются.

Карта архитектуры, DSM-измерения, перечень auto-generated исходников и разрешённые
общерепозиторные настройки warning rules — нейтральные `Details` только в verbose.
Причины NotApplicable и Incomplete сохраняются. Details не содержат списков проблем.
Граф разделяется проверками в пределах одного запуска, без кеша между запусками.
Проверки не прекращаются из-за findings соседнего правила; Incomplete не превращается
в Failed из-за уже доказанных required findings.

## Consequences

### Positive

- Каждый архитектурный verdict виден в реестре, help, explain и отчёте со своей policy.
- Нельзя получить скрытое advisory-нарушение, обходя required.
- Переходное отключение одного правила не выключает остальные архитектурные проверки.

### Negative / Risks

- В tracked policy восемь ключей вместо одного; это намеренная цена явного состояния.
- Эвристические рекомендации больше не выводятся; решения о группировке и связности
  остаются на ревью с учётом предметной области.
- Исторические ADR и маршрут upgrade описывают прежние правила только как историю.
